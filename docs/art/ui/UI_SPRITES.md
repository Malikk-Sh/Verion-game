# Спрайты интерфейса S1.1

3 октября 2026: по поручению Малика векторные заглушки предметов заменены изображениями в стиле утверждённых макетов инвентаря и костюма. Созданы через OpenAI image_gen с этими макетами как стилевыми референсами. Стабильные ID, количество предметов, баланс и формат сохранения не менялись.

## Набор и подключение

Все 11 предметов, реализованных в `src/game/defs.ts`, имеют прозрачный спрайт `src/assets/items/<itemId>.webp`: мультитул, баллон, пища, железо, медь, лёд, камень, шлем, нагрудник с рукавами, поножи, ботинки. Цвета снаряжения: белый/оранжевый/графит; руда и лёд различаются по материалу и цвету. Направление света — сверху слева, без пола и фоновой сцены.

Оригиналы генерировались как PNG; игровые файлы преобразованы в WebP RGBA 512×512, качество 90, без перерисовки содержимого. Вместе — 565 284 байта (≈552 КиБ). [Манифест](SPRITE_MANIFEST.json) содержит prompts, размеры, объём, SHA-256 оригиналов и игровых файлов. Файлы WebP — канонические ассеты этой версии; восстановление не требует генератора или внешнего CDN.

`ITEM_ART` в `src/ui/art.ts` импортирует файлы статически. Все варианты отображения используют один спрайт: быстрый доступ, ячейка рюкзака, мини-слот костюма, баллон, крупное описание, перетаскивание и список замены. Vite создаёт локальные хешированные URL; `tools/build_standalone.mjs` встраивает изображения в автономный HTML через loader `dataurl`. Внешних изображений нет.

Фигура костюма собирается в DOM из четырёх растровых частей через `FIGURE_ART.parts`. Для ботинок используется отдельный прозрачный `src/assets/figure/suit_boots.webp` с широкой постановкой ног. Два ботинка из одного спрайта совмещены каждый со своей штаниной CSS-масками; компактная пара в ячейках сохраняется. Внутренний холст 2:3 сохраняет выравнивание в карточке и большом окне, а подсветка применяется после разделения пары. Каждый слой реагирует на состояние соответствующего слота: надетая часть видна, выбранная подсвечена, снятая показывается слабым серым силуэтом для ориентира. Сборка — иллюстрация экипировки, не 3D-модель. Ботинки и поножи — отдельные слои; будущие варианты можно подключить через реестр. Векторные контуры пустых слотов и функциональные пиктограммы кнопок сохранены.

## Проверка отображения

`npm run verify:art` создаёт отдельное тестовое сохранение с наполненными слотами в чистом контексте браузера. Оно не меняет стартовый комплект игры. Проверяются шесть изображений быстрого доступа, загрузка и прозрачность всех 11 спрайтов, отсутствие выхода изображений за контейнеры, три экрана на 844×390 / 1366×768 / 667×320, выбор части, снятие и надевание шлема, встроенные спрайты автономного HTML и отсутствие ошибок браузера. Снимки и JSON-отчёт пишутся в `artifacts/` (не коммитятся).

После первого просмотра исправлено поведение CSS: растровые изображения не должны задавать минимальный размер flex/grid-контейнеру и перекрывать подписи или действия. Изображения размещены абсолютно внутри `.art` с `object-fit: contain`. Снимок делается после загрузки изображений и завершения анимации открытия панели.

Проверки используют Chromium с программным WebGL. После финальной проверки: `npm test` — 38/38, `verify:s1` — 19/19, `verify:art` — 6/6; сборка и статический валидатор проходят. [Игровые скриншоты](screenshots/) показывают тестовый наполненный рюкзак; это не новый стартовый комплект. На узком экране компас ограничен промежутком между индикаторами и меню; на коротком — рюкзак/описания прокручиваются, ячейки остаются ≥48 px.

Производительность и качество касаний на физическом телефоне не измерены. Процедурная 3D-модель инструмента в руке, модели мира и неработающие пока модули костюма относятся к отдельным задачам.
