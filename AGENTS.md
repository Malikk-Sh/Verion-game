## Обновление

- Менять связанные главы, каталог, сводку и память согласованно. Не только дописывать новое решение в конец противоречащего текста.
- Все числа — B0 до плейтестов. Отличать расчёт/статическую проверку данных от игры на телефоне.
- Рецепты определяются `tools/build_design_catalog.py` → `docs/data/catalog.json` → `docs/spec/04_RECIPES.md`. При изменениях запускать генератор и `tools/validate_design.py`, не редактировать только производную таблицу. После проверки запускать `tools/build_full_gdd.py`, чтобы единый файл `docs/GDD_Vireon_FULL.md` совпадал с главами.
- Валидатор проверяет качественную достижимость, не доказывает геометрию/достаточность количества ресурсов/темп/FPS. Не расширять его выводы.
- Значимые новые решения показывать пользователю кратким списком; пользователь может поправить их. Не требуется разрешение на каждую обратимую редакционную правку в рамках его поручения.
- Сохранять названия Vireon / Verion-game как есть. Не включать токены или служебные данные среды.

## Рамки

Three.js/WebGL2, mobile-first landscape, одиночная игра, русский язык. IndexedDB для сохранений + экспорт/импорт JSON-файла; localStorage только настройки. Нет сервера/обязательного аккаунта, офлайн-прогресса, полной разборки планет или динамического затопления шахт. Покинутые миры работают только при активных игровых часах, без урона от мобов/погоды.

Первая версия: Вердана + Нива + один тип астероида + полный наземный путь. Станция и торговля после неё. Пирра — Expansion 2. Не увеличивать состав первой версии молча.

Документация не означает разрешение автоматически развернуть публичную игру или начать весь кодовый проект, если текущая задача только редактирует GDD. При задаче реализации следовать этапам `docs/spec/08_BALANCE_QA.md`. Физические устройства и замеры обязательны перед обещанием производительности; отсутствующие тесты прямо отмечать.
